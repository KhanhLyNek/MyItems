# Paper 26.3 migration tracker — MyItems

**Status: in progress; NOT a verified Paper 26.3 build.** The repository's existing default branch is `master` (there is no `main` branch). Changes are being committed directly to `master`.

## Required platform

- Java 25; Paper API `io.papermc.paper:paper-api:26.3.build.+`.
- AgarthaLib compiled and tested against the same Paper 26.3 API. MyItems declares `depend: [AgarthaLib]` in `resources/plugin.yml`.
- Plugin sources are from Procyon decompilation and have no committed Maven/Gradle build configuration at migration start.

## Gameplay compatibility contract

- Do not change weapon ability IDs, formulas, damage sources, target selection, range, cooldown, duration in ticks, level/grade scaling or amplifier.
- Do not delete the existing temporary block, metadata, sound and particle behavior of `AbilityWeaponVenomBlast`; migrate the underlying API/bridge instead.
- Preserve config aliases, lore identifiers and serialized item configuration semantics.

## Implemented (source changes; NOT runtime verified)

- [x] `PassiveEffectEnum.getPotion()` now returns current Bukkit/Paper `PotionEffectType` constants:
  - `FAST_DIGGING -> HASTE`
  - `SLOW_DIGGING -> MINING_FATIGUE`
  - `INCREASE_DAMAGE -> STRENGTH`
  - `DAMAGE_RESISTANCE -> RESISTANCE`
  - `JUMP -> JUMP_BOOST`
  - `CONFUSION -> NAUSEA`
  - `SLOW -> SLOWNESS`.
- [x] Existing passive buff/debuff IDs, grade values and spell logic left unchanged.

## Automated compatibility contract (active in GitHub Actions)

The committed `.github/compatibility-baseline.json` freezes all existing entries from `resources/plugin.yml`, `resources/Resources/command.yml` and `resources/Configuration/ability_weapon.yml`. The Python CI check `.github/scripts/check_legacy_contract.py` fails if previously supported command aliases, permissions, ability identifiers, or original scaling/duration/damage settings are deleted or changed. Adding new commands or optional settings remains possible.

This check currently covers **20 commands, 25 ability configurations, 63 subcommand IDs**, and their original permission children. The existing `Venom_Blast` source ID is checked. It is not a gameplay simulation; a successful check does not prove runtime compatibility.

**Do not deploy to production yet.** The full multi-plugin build still fails due to old NMS references and missing/incompatible integration APIs. Existing custom item raw NBT still needs safe migration using real representative item backups. Never rewrite historical item data just to pass a build.

## Stronger regression gates (2026-10-30)

- Source-integrity baseline protects all **25 original weapon skill Java files** and all **18 YAML resources**, including commands, templates, item generator, socket configuration, messages and default abilities. The CI check fails on any unreviewed modification or deletion; additive changes need an explicit baseline review.
- The existing semantic compatibility test separately checks 20 top-level commands, their aliases, 63 subcommands, ability settings and permissions. Both checks must pass.
- The new source-wide scanner covers every Java class in MyItems and the checked-out AgarthaLib dependency, surfacing NMS/CraftBukkit/reflection/integration migration risks in the GitHub Actions summary.
- The AgarthaLib modern item adapter has executable Java tests for long UTF-8 lists, preview PDC format compatibility and malformed data. Historical raw NBT migration is still NOT implemented.
- No damage, target selection, cooldown, tick timing, original ability sources or shipped YAML have been changed in this pass. However no Paper 26.3 gameplay runtime verification has passed, so production deployment is unsafe.

## Paper 26.3 bridge progress and outstanding behavior checks

AgarthaLib now contains a Paper player adapter (locale, absorption, hide entity and hand swing) and an Adventure adapter for action bar, title and subtitle. Java 25 isolated compilation checks are included in the dependency build invoked by this repository's Actions.

The **25 original MyItems weapon ability files and 18 YAML resources remain protected by hash-based CI checks**. The underlying NMS implementation changed, not the source-level gameplay formulas. This is not equivalent to verified runtime behavior.

Before enabling these paths for players, smoke-test absorption hearts and maximum absorption, correct visibility/reappearance of entities, animation visibility/range, action-bar priority/cooldowns, title and subtitle timing, and formatting from historical configs. New Paper entity hiding persists differently from the previous one-off packet approach and could affect visibility if not reviewed.

**Known gaps:** The old custom JSON message DSL/click/hover-item API remains unfinished, as does safe inventory title replacement. Paper marks `InventoryView.setTitle` unsupported/broken, so it must not be used just to make an old call compile. The full AgarthaLib build is blocked by NMS and external plugins, so MyItems cannot yet build or run on the test server.

## Paper 26.3 block animation compatibility

The AgarthaLib block-animation bridge is now backed by `Player.sendBlockDamage` rather than a versioned NMS packet. The original `BridgeBlock.blockBreakAnimation` overloads, source ID and coordinates remain in place. Java 25 CI covers the existing interface and numeric stage mapping.

There are no edits to any MyItems ability Java source or existing YAML. Runtime crack overlay progression, clearing, viewer visibility and skill timing still require server tests. Do not treat these isolated checks as full gameplay validation.

## Paper 26.3 potion name/ID regression tests and optional placeholder integration

AgarthaLib now checks the real `PotionUtil` and `PotionTypeEnum` against Paper 26.3 and executes Java-based tests for the historical 1–32 potion effect IDs plus old effect aliases. The underlying ability class implementations and shipped YAML are unchanged. The existing formula `PotionEffect(potion, duration, grade - 1, ambient, particles)` has not been modified.

The optional MVdW placeholder hook no longer needs the legacy external API JAR to compile. It retains `setPlaceholders(OfflinePlayer, String)` and original MVdW placeholder syntax; it loads the actual plugin method only when available. The modern PlaceholderAPI hook remains separately supported.

Passing the isolated checks is not a full server-play test. Validate effect duration, amplifiers, zombie/undead poison behavior, PvP targeting and placeholders with actual game fixtures before release; full AgarthaLib/MyItems compilation still fails due to other NMS and external dependencies.

## FeatherBoard scoreboard integration (Paper 26.3 migration)

The optional FeatherBoard hook in AgarthaLib now resolves the external FeatherBoard API lazily and keeps its historic public scoreboard operations. It does not toggle a scoreboard when the existing state cannot be determined. Isolated CI compiles the actual adapter and tests the public methods with a CI-only fake API, including a missing-API scenario; it does not include the fake class in any production JAR.

MyItems' original 25 skill implementations, 18 YAML resources, existing command and permission identifiers remain unchanged. Full dependency build and runtime compatibility with the installed FeatherBoard version still need verification.

## AgarthaLib dependency migration: EssentialsX, LangUtils, Towny, MVdW (2026-10-30)

The linked AgarthaLib `master` now independently compiles the original Essentials warp, LangUtils language, Towny group and custom MVdW placeholder registration adapters against Java 25/Paper 26.3 (with published Towny API as `compileOnly`). Verify town/group IDs, online-player filtering, item placeholders, locale text and warp world filtering on real matching plugin versions before deployment.

**No release/deployment:** Full AgarthaLib compilation still fails on remaining NMS code and numerous optional plugin API dependencies. Because MyItems depends on it, full MyItems compilation and Paper runtime gameplay compatibility remain unverified.

## Shared PAPI 2.12.3, EssentialsX and Vault APIs (2026-10-30)

- Both repos now pin Paper API `26.3.build.230-stable`, PlaceholderAPI `2.12.3`, VaultAPI `1.7` and the same AgarthaLib `2.17.2-paper26.3-SNAPSHOT` artifact. CI rejects drift in these coordinates and rejects VaultAPI's obsolete Bukkit 1.13 transitive dependency.
- `ReplacerPlaceholderAPIBuild` has migrated from removed `PlaceholderHook` registration to supported, persistent `PlaceholderExpansion`. The original `myitems` prefix, `hook()` entrypoint and dynamic `PlaceholderManager.getReplacement(player, identifier)` are preserved. That manager still computes the *original* lore, item attributes, abilities, power, cooldown, etc.; no formula or YAML value is replaced.
- `ReplacerMVDWPlaceholderAPIBuild` now delegates optional registration to AgarthaLib's `Paper26MVdWRegistration` and retains the exact original `myitems_*` wildcard and callback suffix. No hard dependency on obsolete `be.maximvdw.placeholderapi` classes is required.
- Separate CI task `compilePaper26MyItemsPlaceholderBridges` compiles the **actual** two MyItems adapter sources with Java 25/Paper 26.3/PAPI 2.12.3 plus AgarthaLib's isolated modern bridge output; CI-only MyItems class signatures never enter production. This task runs even while full AgarthaLib NMS migration is not complete.
- The EssentialsX 2.22.0 release API's warp methods have been checked against published source, but EssentialsX 2.22.0 does not claim official 26.3 runtime support; its existing AgarthaLib integration remains optional and is not silently replaced with a different warp database.
- The original Vault plugin is 1.7.3 and has no declared 26.3 compatibility on its original resource; VaultUnlocked 2.20.3 declares Paper 26.3 support and retains plugin name `Vault` and the standard economy service contract. Never install both simultaneously.
- PlaceholderAPI's eCloud Player expansion is separate. For testing `%player_name%`, install it with `/papi ecloud download Player`, then `/papi reload`. Test custom `%myitems_...%` values for the exact existing identifiers from your configs; **do not invent renamed abilities**.

**Do not publish/deploy:** Existing 25 original ability classes and all 18 YAML resources remain protected and unchanged, but full AgarthaLib/MyItems compilation, historic NBT item compatibility and real Paper 26.3 combat/skill smoke tests still need to pass. User-stored items and economy accounts must never be rewritten just to make CI green.
