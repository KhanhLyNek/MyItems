# Paper 26.3 migration tracker — MyItems

**Status: in progress; NOT a verified Paper 26.3 build.** The repository's existing default branch is `master` (there is no `main` branch). Changes are being committed directly to `master`.

## Required platform

- Java 25; Paper API `io.papermc.paper:paper-api:26.3.build.+`.
- AgarthaLib compiled and tested against the same Paper 26.3 API. MyItems declares `depend: [AgarthaLib]` in `resources/plugin.yml`.
- Plugin sources are from Procyon decompilation and have no committed Maven/Gradle build configuration at migration start.

## Gameplay compatibility contract

- Do not change weapon ability IDs, formulas, damage sources, target selection, range, cooldown, duration in ticks, level/grade scaling or amplifier.
- Do not delete the existing temporary block, metadata, sound and particle behavior of `AbilityWeaponVenomBlast`; migrate the underlying API/bridge instead.
- Preserve config aliases, lore identifiers and serialized item configuration semantics.

## Implemented (source changes; NOT runtime verified)

- [x] Existing passive buff/debuff IDs, grade values and spell logic left unchanged.

## Automated compatibility contract (active in GitHub Actions)

The committed `.github/compatibility-baseline.json` freezes all existing entries from `resources/plugin.yml`, `resources/Resources/command.yml` and `resources/Configuration/ability_weapon.yml`. The Python CI check `.github/scripts/check_legacy_contract.py` fails if previously supported command aliases, permissions, ability identifiers, or original scaling/duration/damage settings are deleted or changed. Adding new commands or optional settings remains possible.

This check currently covers **20 commands, 25 ability configurations, 63 subcommand IDs**, and their original permission children. The existing `Venom_Blast` source ID is checked. It is not a gameplay simulation; a successful check does not prove runtime compatibility.

**Do not deploy to production yet.** The full multi-plugin build still fails due to old NMS references and missing/incompatible integration APIs. Existing custom item raw NBT still needs safe migration using real representative item backups. Never rewrite historical item data just to pass a build.

## Stronger regression gates (2026-10-30)

- Source-integrity baseline protects all **25 original weapon skill Java files** and all **18 YAML resources**, including commands, templates, item generator, socket configuration, messages and default abilities. The CI check fails on any unreviewed modification or deletion; additive changes need an explicit baseline review.
- The existing semantic compatibility test separately checks 20 top-level commands, their aliases, 63 subcommands, ability settings and permissions. Both checks must pass.
- The new source-wide scanner covers every Java class in MyItems and the checked-out AgarthaLib dependency, surfacing NMS/CraftBukkit/reflection/integration migration risks in the GitHub Actions summary.
- The AgarthaLib modern item adapter has executable Java tests for long UTF-8 lists, preview PDC format compatibility and malformed data. Historical raw NBT migration is still NOT implemented.
- No damage, target selection, cooldown, tick timing, original ability sources or shipped YAML have been changed in this pass. However no Paper 26.3 gameplay runtime verification has passed, so production deployment is unsafe.

## Paper 26.3 bridge progress and outstanding behavior checks

AgarthaLib now contains a Paper player adapter (locale, absorption, hide entity and hand swing) and an Adventure adapter for action bar, title and subtitle. Java 25 isolated compilation checks are included in the dependency build invoked by this repository's Actions.

The **25 original MyItems weapon ability files and 18 YAML resources remain protected by hash-based CI checks**. The underlying NMS implementation changed, not the source-level gameplay formulas. This is not equivalent to verified runtime behavior.

Before enabling these paths for players, smoke-test absorption hearts and maximum absorption, correct visibility/reappearance of entities, animation visibility/range, action-bar priority/cooldowns, title and subtitle timing, and formatting from historical configs. New Paper entity hiding persists differently from the previous one-off packet approach and could affect visibility if not reviewed.

**Known gaps:** The old custom JSON message DSL/click/hover-item API remains unfinished, as does safe inventory title replacement. Paper marks `InventoryView.setTitle` unsupported/broken, so it must not be used just to make an old call compile. The full AgarthaLib build is blocked by NMS and external plugins, so MyItems cannot yet build or run on the test server.
